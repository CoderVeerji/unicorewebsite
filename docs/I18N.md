# Languages

The site is published in nine languages. English is the source; the other
eight are built copies.

| | | |
|---|---|---|
| `/` | English | source language |
| `/hi/` | हिन्दी | Hindi |
| `/mr/` | मराठी | Marathi |
| `/gu/` | ગુજરાતી | Gujarati |
| `/ta/` | தமிழ் | Tamil |
| `/te/` | తెలుగు | Telugu |
| `/kn/` | ಕನ್ನಡ | Kannada |
| `/bn/` | বাংলা | Bengali |
| `/pa/` | ਪੰਜਾਬੀ | Punjabi |

**Every translation needs a native speaker's read before launch.** They were
written in one pass and nobody who speaks these languages has checked them.
Fixing one is editing one line of JSON — see below.

## How it works

The eight `.astro` pages stay monolingual English. Nothing in `src/pages` or
`src/components` knows other languages exist. After Astro writes `dist/`, the
integration in `integrations/i18n.mjs` makes one copy of every page per
locale, replacing the text it has a translation for:

```
dist/products.html  ->  dist/hi/products.html, dist/mr/products.html, ...
```

Links inside the pages are relative (`products.html`), so inside `dist/hi/`
they resolve to `/hi/products.html` on their own. Assets are absolute
(`/_astro/...`) and are shared, not duplicated.

Fallback is **per string**, not per page: a locale with twelve translated
strings renders those twelve and the rest in English. Nothing is ever blank.

## Files

| file | what it is |
|---|---|
| `src/i18n/locales.mjs` | the list of languages |
| `src/i18n/strings.json` | every English string, keyed by a short stable id — **generated, do not hand-edit** |
| `src/i18n/<code>.json` | one language's translations, keyed by the same ids |
| `src/i18n/tokenise.mjs` | finds the translatable text in built HTML |
| `integrations/i18n.mjs` | the build step |
| `scripts/i18n-extract.mjs` | regenerates `strings.json` |
| `scripts/i18n-merge.mjs` | merges a partial file into a locale |
| `scripts/i18n-report.mjs` | coverage table |

## Fixing a translation

1. `npm run i18n:report -- hi` prints what is missing, or search
   `src/i18n/strings.json` for the English to get its id.
2. Edit that id's value in `src/i18n/hi.json`.
3. `npm run build`.

## Changing English copy

An id is a hash of the English text, so editing English changes the id and
the old translation goes stale **loudly** rather than silently staying wrong:

```
npm run build && npm run i18n:extract   # refresh strings.json
npm run i18n:report                     # see what each language now lacks
```

Until a language is updated, that one string falls back to English.

## Adding a language

1. Add a row to `src/i18n/locales.mjs`.
2. `npm run build && npm run i18n:extract`.
3. `npm run i18n:report -- <code> > /tmp/<code>.json`, translate the values,
   then `node scripts/i18n-merge.mjs <code> /tmp/<code>.json`.
4. Build. A language with no file is skipped, not half-built.

## What is deliberately left in English

Handled in `src/i18n/tokenise.mjs`:

- the brand name (`Unicore`, `Unicore Lubricants`)
- viscosity and product grades (`15W-40`, `EP-90`)
- email and domain placeholders
- `[to be confirmed by Unicore]` and the `[Photograph: ...]` placeholders —
  these are a to-do list for the client, not copy for a visitor
- the language picker's own list, marked `data-i18n-skip`, because a language
  is always named in its own language

Strings that JavaScript writes at runtime (the countdown wording, the theme
toggle's two aria-labels, the rotating hero phrases) live in `data-*`
attributes on the markup so they can be translated with everything else.

## Fonts

The two brand fonts cover Latin only. On a translated page the browser falls
back to the reader's system face for Devanagari, Tamil, Telugu, Kannada,
Bengali, Gujarati and Gurmukhi. This is deliberate — webfonts for eight
scripts would cost more than the whole site weighs. `src/styles/global.css`
gives non-English pages more line-height and smaller display sizes, since
those scripts carry marks above and below the baseline.
